Build a responsive web app called "CareCompass", an AI Patient Support & Hospital Navigator. It is NOT a diagnostic tool. It helps patients navigate hospital services: finding the right department, preparing for a visit, and understanding their own documents.

## CORE FEATURE (the "Navigator" page)
The user describes their situation in messy natural language and optionally uploads documents (prescription photo, PDF, or pasted text).
Example input: "I need to see a skin specialist and I have my previous prescription."

Send the text and any uploaded documents to an LLM (Anthropic Claude API; read the key from the Replit secret ANTHROPIC_API_KEY; make the backend call, never expose the key in the frontend). The LLM must return structured JSON, which the UI renders as result cards:

1. Recommended Department: department name, a one-line reason, and urgency level (routine / soon / urgent-seek-care-now)
2. Extracted Information: medicines, dosages, dates, doctor names, and previous conditions mentioned in the documents (only what is actually written; never guess)
3. Visit Checklist: an interactive checkbox list (documents to carry, ID/insurance, fasting or no-fasting, arrive-early, things to note down beforehand)
4. Document Summary: a plain-language summary of the uploaded prescription or report
5. Questions to Ask the Doctor: 5-7 relevant questions, with a "Copy" button

Rules for the LLM system prompt:
- Never diagnose, never recommend or change medicines or doses, never interpret results as a diagnosis.
- If the user describes emergency symptoms (chest pain, trouble breathing, heavy bleeding, stroke signs, etc.), show a red banner telling them to seek emergency care immediately.
- If the document is unreadable or information is missing, say so instead of inventing details.
- Always return valid JSON matching a fixed schema.

Add buttons: "Download checklist as PDF", "Print", and "Start new query". Show a loading skeleton while the AI works. Always show a footer disclaimer: "This tool provides navigation help only and is not medical advice."

## PAGES
- Home (landing page, see design below)
- Navigator (the core tool)
- How It Works (3 steps: Describe, Upload, Get Your Plan)
- Departments (a grid of 10-12 departments: Dermatology, Cardiology, Orthopedics, ENT, Pediatrics, Gynecology, Neurology, Ophthalmology, General Medicine, etc., each with an icon and a short description)
- FAQ and Contact

## TECH
React + Vite + Tailwind CSS on the frontend, Node/Express (or FastAPI) on the backend. Use Lucide icons. Support file upload for images and PDFs (use the LLM's vision/document input). Keep everything in one Replit project with a working "Run" button. Don't store patient data permanently; process in memory only and add a small privacy note.

## UI/UX DESIGN (follow this closely, modeled on a modern healthcare landing page)

- Colors: soft mint-to-white gradient background with a subtle blurred blobs effect; deep navy (#1E1B4B-ish) for headings; royal blue (#1D6FE8) for primary buttons; violet/purple (#7C6AE6) for accent and the main CTA in the navbar; warm yellow (#FFC83D) as a decorative accent shape.
- Font: Poppins or Jost. Bold, large navy hero headline; muted gray body text.
- Navbar: logo (a small blue rounded square with a pulse icon + brand name) on the left; links Home, How It Works, Departments, Contact in the center; a purple rounded button "Start Navigating" on the right. Sticky with a translucent blur background.
- Hero section (two columns):

  - Right: arch-shaped (pill/rounded-top) image frames, one yellow and one purple, with friendly doctor/patient photos (use placeholder stock images), overlapping slightly.
  - Floating white rounded cards on top of the images: one chat bubble ("Hello, I need a skin specialist"), and one small "Meet our Departments" card with a row of tiny avatars and a "+12" teal badge.
- Stats row under the hero: four items with bold navy numbers and light gray labels (e.g., 12+ Departments, 5 Document Types, 7 Languages, 24/7 Available).
- "Meet Our Departments" section: cards with arch-shaped image tops, a name and a specialty label on a translucent bar at the bottom.
- "How It Works" section: 3 numbered cards with icons and soft shadows.

- FAQ: accordion with rounded white cards.
- Footer: navy background, 4 columns, medical disclaimer.
- Navigator page: a large white rounded card with a chat-style textarea, a drag-and-drop upload zone with a dashed border, suggestion chips ("I need a skin specialist", "I have a prescription", "My child has a fever, which doctor?"), and results displayed as colorful stacked cards, each with an icon header (blue, purple, teal, yellow accents).
- Micro-interactions: smooth hover lifts on cards, fade-in-up on scroll, animated progress steps while the AI processes ("Reading your documents...", "Finding the right department...").
- Fully responsive (mobile-first) with accessible contrast and large tap targets.
